# Todoist Execute Today

Skip the "open Todoist, find task, paste prompt" friction. Detect the current project from cwd, fetch today's tasks, extract the kickoff prompt from the top one, and start working.

This is the **read** half of the kickoff-prompt loop. The **write** half (`todoist-kickoff-prompt`) appended `## Kickoff Prompt` sections during triage. This skill harvests them.

## Prerequisites

- `td` CLI installed and authenticated
- Tasks have kickoff prompts in their descriptions (run `todoist-kickoff-prompt` first if not)

## Workflow

### 1. Resolve cwd → Todoist project ID

Look for `.todoist-project` in the current directory (or any ancestor up to `$HOME`):

```bash
# Walk up looking for .todoist-project
dir="$PWD"
while [[ "$dir" != "$HOME" && "$dir" != "/" ]]; do
  if [[ -f "$dir/.todoist-project" ]]; then
    PROJECT_ID=$(cat "$dir/.todoist-project")
    break
  fi
  dir=$(dirname "$dir")
done
```

**If not found**, run first-run interactive setup:

1. Run `td project list` to show available projects
2. Ask user via `AskUserQuestion` which project maps to this directory (offer top 4 fuzzy matches against cwd basename)
3. Write the chosen ID to `./.todoist-project` (single line, just the ID — no frontmatter)
4. Suggest the user add `.todoist-project` to `.gitignore` (it's a per-machine pointer, not a shared artifact). Skill should NOT modify `.gitignore` itself — that's a project-conventions decision.

**Idempotency:** if `.todoist-project` already exists, use it without re-prompting. To reset, user deletes the file manually.

### 2. Fetch today's + overdue tasks

```bash
td task list --project "id:$PROJECT_ID" --filter "(today | overdue)"
```

If `--filter` isn't supported by your `td` version, fall back to filtering by date manually after fetching all project tasks.

### 3. Pick the top task

**Default ordering** (override only if user specifies):

1. P1 first, then P2, P3, P4
2. Within priority: oldest due date first (most-overdue → today)
3. Tie-break: lowest task-ID character order (deterministic, doesn't matter much)

If no tasks match, surface the next-soonest dated task and ask whether to proceed.

### 4. Read the chosen task

```bash
td task view "$TOP_ID"
```

### 5. Extract the kickoff prompt

Look for the `## Kickoff Prompt` heading in the description. Everything from that heading to the next `---` (or end of description) is the prompt body.

```bash
description=$(td task view "$TOP_ID" 2>/dev/null | awk '/^Description:/{flag=1; next} flag')
prompt=$(printf '%s\n' "$description" | awk '
  /^## Kickoff Prompt/ { capture=1; next }
  /^\*Generated by todoist-kickoff-prompt\*/ { capture=0 }
  capture && /^---$/ { capture=0 }
  capture { print }
')
```

**If no kickoff prompt found:**

1. Surface the task as-is (full description)
2. Offer two paths:
   - "Generate kickoff prompt now" → invoke `todoist-kickoff-prompt` for this single ID, then re-read
   - "Proceed without prompt" → pass the raw description to the agent and start work

Don't auto-generate without asking — the user might want to read the description directly first.

### 6. Present + execute

Print:

```
🎯 Today's top: <task title>
   Priority P<n> · Due <date> · Project <name>
   Task: <Todoist URL>

[kickoff prompt body here]

Ready to start?
```

Then **wait for user confirmation** before executing. Don't auto-launch — give the user a chance to bump priority, defer, or pick a different task.

### 7. Optional: mark task in-progress

Todoist doesn't have a native in-progress status. Options:

- Add a label `in-progress` (cheap, visible in UI)
- Add a comment timestamping start (`td comment add <id> "started YYYY-MM-DD HH:MM"`)
- Skip — just start work; user closes when done

Default: skip. Status tracking adds friction and doesn't change behavior. If the user wants it, they'll ask.

### 8. Hand off to execution

Once the user confirms, the kickoff prompt becomes the agent's marching orders. Read the cold-start refs (files, beads, ADRs), then execute the "next concrete action."

## Composability

| Caller | How |
|---|---|
| Standalone | `Skill todoist-execute-today` from a project directory |
| With explicit ID | `Skill todoist-execute-today 6abc...` — skip selection, jump to that task |
| Filtered | `Skill todoist-execute-today --priority p1` — only P1 tasks |
| After triage | `todoist-project-triage` step 14 already offers `todoist-kickoff-prompt`; user can run this skill on the next session to pick up where they left off |

## Common Gotchas

- **`.todoist-project` is per-machine.** Don't commit it. Suggest the user add it to `.gitignore`; don't auto-edit `.gitignore`.
- **Multiple tasks tied for "top".** Print the rank list, let user pick. Don't pick arbitrarily.
- **Task has no kickoff prompt.** Description-only fallback works but is lower-fidelity. Offer to generate-then-execute instead of forcing a choice.
- **Project ID changes.** If `td project list` no longer has the cached ID (renamed/deleted), surface the error and ask to re-pick.
- **Recurring tasks.** `td today` includes recurring instances. The kickoff prompt was written for the original instance — verify it still applies before executing (recurring task descriptions are usually static, but goal/dates may have drifted).

## Anti-patterns

- **Auto-executing without user confirmation.** Always present + wait. The user might want to switch tasks based on what shows up.
- **Modifying `.gitignore` without asking.** Suggest, don't act.
- **Falling back to "any task" when today is empty.** If nothing's dated today, ask — don't silently grab tomorrow's work.
- **Hardcoding the working directory.** Walk up from `$PWD` to find `.todoist-project` — supports running from sub-directories.

## What this skill is NOT

- Not a planner — it doesn't decide priority, just reads what triage already set
- Not a kickoff-prompt generator — that's `todoist-kickoff-prompt`'s job
- Not an executor — once the prompt is presented and the user confirms, execution is just normal agent work
